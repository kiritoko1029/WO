## 修复 + 新功能方案

### Bug 修复：麦克风无声

**根因**：RNNoise 降噪功能存在致命缺陷：
1. `PROCESSOR_BUFFER_SIZE=2048` < `RNNOISE_FRAME_SIZE×3=2880`，导致 `frameCount=0`，降噪完全无效
2. `@shiguredo/rnnoise-wasm` 使用 `import.meta.url` 加载 WASM，在打包后的 Electron app 内（`file://` 协议 + asar 归档）会失败
3. 当降噪强度 ≠ `off` 时，`voiceConstraints` 设置 `noiseSuppression: false`，关闭了浏览器原生降噪
4. `createNoiseSuppressor` 在 packaged 环境中可能创建了一个 AudioContext graph 但 WASM 加载失败 → 虽然 fallback 返回原始 track，但 `getUserMedia` 已用 `noiseSuppression: false` 采集，且 `switchMicrophone`（在 `setNoiseIntensity` 时触发）可能导致 sender track 断开

**修复方案**：移除 RNNoise Web Audio 链路，始终使用浏览器原生 `noiseSuppression: true`。

- **`voice-controller.ts`**：`voiceConstraints` 中 `noiseSuppression` 始终为 `true`（移除 `noiseIntensity` 条件）；`capture()` 中移除 `createNoiseSuppressor` / `noiseSuppressor.process` 调用
- **`noise-suppressor.ts`**：保留类型定义和 `localStorage` 持久化逻辑（UI 仍可选），但 `createNoiseSuppressor` 直接返回一个 passthrough suppressor
- **`CallToolbar.tsx`**：降噪下拉改为固定显示"浏览器内置"（或隐藏选项），不再触发 recapture

### 新功能：说话人音量波动指示

**目标**：每个参与者姓名右侧的麦克风图标根据说话音量动态变化（大小或颜色脉冲）。

**方案**：在 `ParticipantSlots` 中，麦克风图标的颜色/透明度随实时音量水平变化。

**数据来源**：
- **本地麦克风**：使用 `RTCPeerConnection.getStats()` 的 outbound-rtp `audioLevel`（Chromium 提供），或用独立的 `AnalyserNode` 更新（频率更高）
- **远端音频**：inbound-rtp 的 `audioLevel`

**实现**：
1. **`call-store.tsx`**：在 stats monitor 的 poll 回调中，从 outbound/inbound stats 提取 `audioLevel`（0–1），更新 `CallSnapshot` 的 `localAudioLevel` 和 `remoteAudioLevel` 字段
2. **`stats-monitor.ts`**：从 RTCStatsReport 的 `media-source` 或 `outbound-rtp`/`inbound-rtp` 记录中读取 `audioLevel`
3. **`CallSnapshot`**：新增 `localAudioLevel: number` 和 `remoteAudioLevel: number`
4. **`ParticipantSlots.tsx`**：接收 `localAudioLevel` 和 `remoteAudioLevel` props，用 CSS `opacity` + `transform: scale()` 动态渲染麦克风图标
5. **`RoomRoute.tsx`**：将 audio level 传入 ParticipantSlots

**UI 效果**：麦克风图标在静默时 `opacity: 0.4`，说话时 `opacity: 1` + `scale(1.15)`，CSS transition 平滑过渡。
